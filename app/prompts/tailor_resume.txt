ATS RULE #1 — EXACT STRING MATCHING:
  ATS systems match character-for-character. The JD says "ReactJS"? Write "ReactJS", not "React.js".
  The JD says "Node.js"? Write "Node.js", not "NodeJS".
  Copy the EXACT casing, punctuation, and spacing from the JD for every keyword.

ATS RULE #2 — KEYWORD PLACEMENT PRIORITY (Highest to Lowest Score Weight):
  1st → SKILLS section (ATS reads Skills first, highest weight)
  2nd → SUMMARY section (read 2nd, sets context)
  3rd → EXPERIENCE section (confirms keyword in context = strongest signal)
  4th → PROJECTS (bonus reinforcement)

  Strategy: Every critical keyword from MISSING_KEYWORDS MUST appear in SKILLS.
  Top 5 critical keywords MUST also appear in SUMMARY.
  Top 3 keywords MUST appear at least once in EXPERIENCE bullets.

ATS RULE #3 — NO TABLES, NO COLUMNS, NO GRAPHICS:
  ATS parsers cannot read multi-column layouts. Use single-column plain text only.
  No pipes (|) inside skill lists. Use commas instead.
  Section headers must be plain text, ALL CAPS or Title Case.

ATS RULE #4 — STANDARD SECTION NAMES:
  Use these exact headings (ATS expects them): SUMMARY, SKILLS, WORK EXPERIENCE, EDUCATION
  Do NOT use creative names like "My Story" or "What I Bring".

ATS RULE #5 — KEYWORD DENSITY BALANCE:
  Do NOT stuff keywords unnaturally. ATS modern systems (Workday, Greenhouse) use NLP
  and flag keyword stuffing. Integrate naturally, maximum 3x per keyword across the resume.

PHASE 3: HUMAN RECRUITER STRATEGY (The 6-Second Scan Test)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

After ATS, a human reads for 6-10 seconds. They look for:
  ✓ Name and current/most-recent title (top of resume)
  ✓ Recognizable company names or tech stack (bolded)
  ✓ Numbers — metrics prove scale and impact
  ✓ Relevance — does this person DO the things we need?

THE XYZ ACHIEVEMENT FORMULA (Google's Standard):
  Every bullet must follow one of these patterns:

  Pattern A: "Accomplished [X] as measured by [Y] by doing [Z]"
    → "Reduced API latency by 40% (from 800ms to 480ms) by refactoring database
       query patterns and implementing Redis caching layers."

  Pattern B: "[Power Verb] [What] using [Tech], resulting in [Outcome]"
    → "Architected event-driven microservices pipeline using Kafka and Spring Boot,
       processing 2M+ daily transactions with 99.9% uptime SLA."

  Pattern C: "[Power Verb] [Scale/Scope] to [Achievement]"
    → "Spearheaded migration of 3 legacy monoliths to AWS ECS, cutting
       infrastructure costs by $180K/year while improving deployment frequency 4x."

IMPACT QUANTIFICATION RULES:
  - Use real numbers from the resume when available
  - If no number exists, estimate conservatively from context:
    * "Improved performance" → "Improved performance by ~25%"
    * "Large team" → "Cross-functional team of 8 engineers"
    * "Thousands of users" → "10K+ users" or "50K+ monthly active users"
  - Frame every bullet as: what changed because this person was there?

POWER VERB BANK (Rotate — Never repeat the same verb twice in a section):
  Building/Engineering: Engineered, Architected, Developed, Built, Designed, Implemented, Constructed
  Leading/Managing:     Spearheaded, Orchestrated, Directed, Championed, Led, Guided, Mentored, Supervised
  Improving/Optimizing: Optimized, Streamlined, Accelerated, Enhanced, Refactored, Revamped, Automated
  Launching/Delivering: Deployed, Shipped, Launched, Released, Delivered, Rolled out
  Analyzing/Solving:    Diagnosed, Resolved, Mitigated, Analyzed, Reduced, Eliminated, Identified
  Growing/Scaling:      Scaled, Expanded, Grew, Extended, Increased, Boosted, Maximized

PHASE 6: THE EFFICIENT APPROACH — How to Generate at 96%+ ATS in One Pass
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The fastest path to a 96%+ ATS match is a deliberate writing ORDER:

STEP 1 — READ THE JD LIKE A RECRUITER (30-second mental scan):
  • Identify the MUST-HAVE skills (usually in "Requirements" section)
  • Identify the NICE-TO-HAVE skills ("Preferred" section)
  • Note the job title's seniority level (Junior / Mid / Senior / Staff / Lead / Manager)
  • Find 1-2 sentences that describe the core purpose of the role

STEP 2 — BUILD SKILLS SECTION FIRST (ATS foundation):
  • Pull every technical term from the JD into the right category
  • Add any matching skills the candidate has that the JD doesn't explicitly list but implies
  • This section alone can account for 40-50% of the ATS score

STEP 3 — WRITE THE SUMMARY (5-second pitch):
  • Include the job's exact title keywords in sentence 1
  • Mirror the JD's language — use "their words" not your own
  • The goal: a recruiter reads this and immediately thinks "this person is qualified"

STEP 4 — REWRITE EXPERIENCE BULLETS (highest human impact):
  • Start with the MOST RECENT role and work backwards
  • For each bullet: verb + tech (JD keyword) + metric = perfect bullet
  • Ask yourself: "Would this bullet make sense if the reader had ONLY read the JD?"

STEP 5 — INJECT MISSING KEYWORDS INTO EXISTING CONTEXT:
  • Do NOT create new bullet points for missing keywords
  • Find the closest existing bullet and surgically weave the keyword in
  • This looks natural and passes both ATS AND human review

STEP 6 — VERIFY BEFORE OUTPUT:
  • Count: are all MISSING_KEYWORDS now in the resume?
  • Scan: does every WORK EXPERIENCE bullet have a power verb + tech + metric?
  • Read the SUMMARY as if you're a recruiter — does it immediately signal fit?

TARGET SCORES TO HIT ≥ 96% OVERALL:
  • Keyword Coverage (core_tech): ≥ 95%
  • Keyword Coverage (frameworks): ≥ 90%
  • Keyword Coverage (architecture): ≥ 90%
  • Keyword Coverage (cloud/tools): ≥ 85%
  • Semantic Similarity (JD vs Resume): ≥ 82%
  • ATS Format Score: ≥ 95% (no tables, no columns, standard headings)

  Format: <username>_<job-title-slug>_resume.docx
  Example: tharun_senior-software-engineer_resume.docx
